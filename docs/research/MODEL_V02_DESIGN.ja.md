# V0.1 Candidate に基づく Model V0.2 設計案

[English](MODEL_V02_DESIGN.md) | [简体中文](MODEL_V02_DESIGN.cn.md) | **日本語**

状態：**長さガードのプレビュー実装済み、2026-09-28**。V0.2 の学習は未実施で、新しい科学モデルの重み、校正、正式公開、精度改善の実測結果はありません。

## 実装済み：V0.2 長さガードのプレビュー

現在の実装は、固定 V0.1 に保守的な**判定保留ポリシー**を追加したものです。
科学モデル V0.2 の学習や精度向上を示すものではありません。

| 正規化後の長さ | 処理 | `final_prediction` |
|---|---|---|
| <250 aa | 全 encoder と分類器をスキップ | `mcp_unreliable_short_sequence` |
| ≥250 aa（250 を含む） | 従来の V0.1 推論 | 既存の五つのモデルラベル |

短配列ラベルは「MCP 判定の信頼性不足：250 aa 未満」を意味します。MCP 陽性でも
陰性でもありません。status は `not_evaluated_short_sequence`、スコアは `NA`、
各 head は `not_reached`、`head3_reached=0`、警告は `length_below_250_aa` です。
空白を除去し大文字化した配列長を使い、X も 1 残基と数えます。全 FASTA を先に
検証し、不正な短配列もエラーにします。全レコード、元のヘッダーと順序を保持します。

250 aa は**利用者が選んだ運用上の保留基準**で、生物学的な最小長でも、それ以上の
精度保証でもありません。メタデータを調べた MCP 陽性 560 例（Train 336、Validation
112、Test 112）に 250 aa 未満はなく、250–299 aa は Train 13 例、全体 22 例です。
これは検証不足を示しますが、短配列の陽性判定が必ず誤りという根拠ではありません。

現在の checkout をインストールするか、モジュールから実行します。

```bash
PYTHONPATH=user-inference-v0.1/src python -m djrmcp_predict_v01.v02_preview predict \
  proteins.faa --outdir results/v02-preview --device cpu
# インストール後: djrmcp-predict-v02-preview predict proteins.faa --outdir results/v02-preview
```

全入力が短い場合は PLM checkpoint、worker、GPU は不要です。対象長の入力には
従来の V0.1 encoder 環境とキャッシュ設定が必要です。既存 Docker wrapper は V0.1
のままなので、更新した環境で preview を明示的に呼び出します。
出力は `predictions.tsv`、`run_metadata.json`、`CHECKSUMS.sha256` です。
TSV の列は同じですが、下流の読み手は保留ラベルへの対応が必要です。メタデータは
`schema_name=djrmcp_v02_policy_preview` とし、ポリシー、評価カバー率、保留数、
適格な部分集合だけの V0.1 実行情報を記録します。V0.1 コマンドと重みは変更せず、
新しいリリースも公開しません。

既存の無フィルター V0/V0.1 benchmark はモデル診断として保持します。運用評価は
<250、250–299、300–349、350–399、400–449、450–499、≥500 aa ごとに
評価カバー率と保留数を別途報告します。250 aa 未満では予測しないため、条件付き
再現率/FPR は**推定不可**です。保留を真陰性にしません。全入力に対する検出再現率
では全陽性を分母に残し、陽性の保留は未検出とします。評価した入力だけの指標・
分母と全体の検出再現率を分けます。現行図は V0.1 cross-fit の結果です。

以下は将来の研究計画です。250 aa 未満の改善基準はガードを外した将来モデルの
診断に用い、独立検証後のポリシー変更を検討するためのものです。現行の保留
パイプラインに対する性能主張や合格条件ではありません。

## 目的と構成

基準は **Model V0.1 Candidate** です。MCP 由来の短い断片の検出率を改善し、
偽陽性と全長入力の性能低下を抑えることを目指します。
[benchmark](../../benchmarks/short_sequence_v1/README.ja.md) の V0 は過去の比較対象です。
まず V0.1 を測定し、モデル変更が必要な長さを確認します。

ESM-2 3B の checkpoint、pooling、精度、長配列処理は維持します。H1/H2 では
全長と断片を併用する学習を検討します。最初の実験では ESM-C 6B の H3 を
維持し、H1/H2 の変更の効果を分離します。候補の閾値は独立に校正し、評価前に
固定します。評価対象の五つのラベルに、短入力の保留ラベルを追加します。

## 今後の学習実験

1. 外側の component 分割を固定し、断片によるデータ拡張は学習 component 内
   だけで行います。親タンパク質、相同 component と全断片は同じ区分に保持します。
2. 全長を残し、最初の候補では 130、150、200、250、300 aa の末端・内部断片を
   検討します。50/100 aa はまずストレステストに使います。断片のラベルは由来を
   示すもので、完全な構造や機能を保証しません。
3. 親ごとの総重みを等しくし、半分を全長、半分を利用可能な断片に配分する案です。
   断片分は長さ間、次に位置間で均等に配分します。断片が作れない親は全重みを
   全長に割り当てます。H1 のクラス／由来別バランスと H2 のクラスバランスを
   親単位の重みの上で維持し、窓数で優遇しません。
4. 最初は分類器の種類とハイパーパラメータを維持します。標準化統計は学習部分
   だけから求めます。PLM の微調整や長さ別の分類器は初期実験の範囲外です。
5. 全長のみの対照と全長＋断片の候補を比較します。初回の閾値校正は全長のみで
   行い、学習拡張の効果を分離します。断片を使う校正は別実験として登録します。
6. 交差検証では各 fold の許可された全長学習データで H3 を一度だけ学習し、
   V0.1 と V0.2 が同じ H3 を使います。H1/H2 を通過する難しい断片が増えるため、
   H3 のエンドツーエンド再現率も評価します。

現在の benchmark は V0/V0.1 の再学習比較だけを実装しています。V0.2 学習
アダプターは未実装です。追加時には方法 ID、学習 manifest、親ごとの重み、
断片生成方針の checksum が必要です。

## 評価と受け入れ案

拡張比率やハイパーパラメータの選択には、外側学習区分内の component 分割を
使います。校正区分は閾値を決め、外側評価区分は設定選択に使いません。既存の
開発データと基準結果は既に確認されているため、比較は内部開発評価です。
正式な改善確認には、独立ラベルを持つ実際の短タンパク質を含む新しい外部
lockbox が必要です。重複検査、配列・ラベルのハッシュ、由来比率、指標を事前に
固定します。人工断片と実際の短タンパク質は別に報告し、過去の protected Test
を自動で開きません。

以下は V0.2 の結果を見る前に登録する**設計目標**で、達成済みではありません。

- 130、150、200 aa の再現率差を等重みで平均し、V0.2−V0.1 の対応あり 95% CI
  下限が 0 より大きいこと。結果を見て最良の長さだけを選びません。
- 各主要長で pooled MCP FPR の CI 上限が 1% 以下、FPR 増分の CI 上限が
  0.5 パーセントポイント以下であること。負例由来ごとの悪化も別途確認します。
- 全長 MCP 再現率差の CI 下限が -1 ポイント以上、FPR 増分の上限が
  0.5 ポイント以下であること。
- 全長 H3 のエンドツーエンド再現率差の CI 下限が、既知の各門で -1 ポイント
  以上であること。上流の失敗も分母に残します。
- 独立サンプル不足、不安定な区間、ゼロ誤りによる退化した bootstrap 区間は
  合格根拠にしません。独立データ追加または境界に妥当な事前登録済みの区間が必要です。

三長さの複合指標、V0.2 学習、正式な合否判定は今後の実装です。不合格なら V0.1
を維持し、自動で昇格しません。

## 配布とバージョン

検証後、学習データ、拡張方針、encoder revision、分類頭、temperature、閾値、
検証した長さ範囲を記録した独立 bundle を作ります。短入力とゲート失敗も含め、
オフライン評価と配布推論の一致をテストします。V0.1 は選択可能な基準として残します。

現在の運用ポリシーは上記の通りです。モデルスコアの意味を維持し、長さだけで
断片性を断定しません。将来の独立した根拠に基づく変更は別バージョンとします。

その後に科学モデル ID とモデルカードを定め、[バージョン対応](../VERSIONING.ja.md)
を更新します。現在のパッケージ `0.2.1` は科学モデル V0.2 ではありません。
今回、既存の release manifest、パッケージのバージョン、重みは変更しません。保存済み embedding
による入力長別の CPU 評価は完了しました。ただし 250 aa 未満に MCP 陽性例がなく、
250–299 aa も 13 例のみです。最短利用長の決定には対応のある切断実験と独立した
短陽性配列の確認が必要です。新規断片の GPU encoding と V0.2 学習は別段階で、
V0.2 学習は実施していません。
