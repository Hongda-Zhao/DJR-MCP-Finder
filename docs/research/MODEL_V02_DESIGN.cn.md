# 基于 V0.1 Candidate 的 Model V0.2 设计方案

状态：**长度保护预览已实现，2026-09-28**。暂不训练 V0.2；没有新的科学模型权重、校准结果、正式发布或准确率提升结论。

## 已实现：V0.2 长度保护预览

当前交付是在冻结 V0.1 上增加保守的**不予判定策略**，没有训练科学模型 V0.2，
也没有声称模型准确率得到提升。

| 标准化后的输入长度 | 处理方式 | `final_prediction` |
|---|---|---|
| <250 aa | 跳过全部编码器和分类头 | `mcp_unreliable_short_sequence` |
| ≥250 aa，含恰好 250 aa | 原样使用 V0.1 推理 | 现有五类模型标签 |

短输入标签含义为 **MCP 不可信：序列短于 250 aa，证据不足**。它既不是 MCP 阳性，
也不是非 MCP。状态为 `not_evaluated_short_sequence`，分数为 `NA`，各头为
`not_reached`，`head3_reached=0`，警告包含 `length_below_250_aa`。
长度按去除 FASTA 序列空白、转换大写后计算，X 计为一个残基。先校验整个文件，
非法短序列仍然报错。混合输入保留全部记录、原始标题和输入顺序。

250 aa 是**用户选择的部署保护阈值**，不是已证实的生物学最短长度，也不保证
≥250 aa 的预测正确。仅检查元数据得到 560 条整理后的 MCP 阳性（Train 336、
Validation 112、Test 112），其中没有 <250 aa 的阳性。Train 在 250–299 aa 有
13 条，全部 560 条中该区间有 22 条。这说明该长度范围验证不足，不能据此说所有
短序列阳性都是假的。

安装当前源码后使用新入口，或直接运行模块：

```bash
PYTHONPATH=user-inference-v0.1/src python -m djrmcp_predict_v01.v02_preview predict \
  proteins.faa --outdir results/v02-preview --device cpu
# 安装后等价命令：djrmcp-predict-v02-preview predict proteins.faa --outdir results/v02-preview
```

全部输入 <250 aa 时，不需要 PLM checkpoint、模型 worker 或 GPU。其余输入仍需
V0.1 的编码器环境和缓存配置。既有 Docker 脚本仍调用 V0.1；使用预览需在更新后的
环境中显式调用新入口。输出仍为 `predictions.tsv`、`run_metadata.json` 和
`CHECKSUMS.sha256`。TSV 列不变，但增加不予判定标签，下游解析器需兼容此值。
元数据使用 `schema_name=djrmcp_v02_policy_preview`，记录策略、评分覆盖率、
不予判定数量，以及仅包含合格输入的嵌套 V0.1 运行信息。
V0.1 命令和冻结权重保持不变；本次不发布新版本。

评测保留现有未过滤的 V0/V0.1 能力 benchmark。部署策略的评价应另行按 <250、
250–299、300–349、350–399、400–449、450–499、≥500 aa 报告评分覆盖率和
不予判定数。<250 aa 因为没有预测，其条件召回率/FPR **不可估计**；不能把不予
判定记为真阴性。计算端到端检出召回率时，全部真实阳性保留在分母，不予判定的
阳性算未检出。已评分样本的指标与分母、全体样本的检出召回率分别报告。
当前图展示 V0.1 分折诊断结果，不是 V0.2 部署策略的实测性能。

下面的训练方案仅是未来研究计划。其中 <250 aa 的改进验收条件用于未来去掉长度
保护后的模型诊断，以判断是否有证据调整保护阈值；不是当前不予判定流程的
性能声明或验收条件。

## 目标与基线

以 **Model V0.1 Candidate** 为基线，提升 MCP 来源短片段的检出能力，同时约束
假阳性率和完整序列性能下降。[短序列 benchmark](../../benchmarks/short_sequence_v1/README.cn.md)
中的 V0 只作历史对照。先测清 V0.1 的能力；有些长度范围可能无需更换模型。

| 模块 | V0.1 Candidate | 首个 V0.2 候选设计 |
|---|---|---|
| H1/H2 编码器 | ESM-2 3B | 保留冻结 checkpoint、pooling、精度和长序列窗口规则 |
| H1 DJR 分类器 | 完整蛋白训练 | 比较完整蛋白与短片段联合训练 |
| H2 MCP 分类器 | 完整 DJR 蛋白训练 | 正负例都加入同样长度、位置的片段 |
| H3 门分类 | ESM-C 6B，复用 V0 分类头 | 首轮保持不变，分离 H1/H2 改动的影响 |
| 阈值 | V0.1 冻结阈值 | 为新候选独立校准，评价前冻结 |
| 输出 | 五类最终标签与分数 | 预览新增短输入不予判定标签；已评分输入保留原标签 |

## 候选训练实验：尚未实现、尚未执行

1. 沿用外层 component 分折，只在训练 component 内生成增强数据。母序列、
   同源 component 和所有片段不得跨训练、校准、评价边界。
2. 完整蛋白始终保留。首轮候选考虑 130、150、200、250、300 aa 的端部和内部
   片段；50/100 aa 先作为压力测试。片段标签表示来源，不宣称片段保留完整结构或功能。
3. 每条母序列的总训练权重相同：初始设计一半给完整序列，一半给可用片段；
   片段权重先在长度间均分，再在该长度的可用位置间均分。没有可用片段时，全部
   权重给完整序列。H1 的类别／来源平衡、H2 的类别平衡必须在母序列权重基础上
   保持，不能让长蛋白或重复阴性因为窗口更多而占更大权重。
4. 首轮保留分类器类型和超参数。标准化统计仅来自训练组。不进行 PLM 微调，
   不引入独立短序列编码器或按长度切换的分类器。
5. 对照为“只用完整序列训练”，实验为“完整序列＋片段”。首轮阈值仍只用完整
   校准蛋白确定，先分离训练增强的贡献。若另测包含片段的校准，需要单独登记，
   不能同时改训练与阈值却把全部效果归于某一项。
6. 面向部署的实验保留 H3。交叉验证时，每折只在许可的完整训练蛋白上拟合一次
   H3，并让 V0.1 对照与 V0.2 共用该折 H3。H1/H2 放行更多短片段后，H3 可能面对
   更难样本，因此必须继续报告 H3 的端到端表现。

## 开发评测与独立确认

目前新增的 benchmark 只实现 V0/V0.1 的分折重拟合，没有 V0.2 增强训练接口。
后续添加 V0.2 时，必须先增加独立方法标识、训练样本清单、母序列权重和片段
策略校验和，再开始训练。

如果要选择增强比例、超参数或长度策略，应在外层训练部分内部进一步按 component
划分；校准组负责阈值，外层评价组不参与选择。既有开发集和基线结果已经被查看，
因此这些比较仍只能支持内部开发结论。

正式提升结论需要新建独立测试集：可信 MCP、cellular DJR、困难 non-DJR、普通
背景，以及有独立标签的真实短蛋白。运行前冻结母序列重叠检查、标签与序列哈希、
来源构成、评价指标和一次性比较方案。人工截短与真实短蛋白分开报告；不自动打开
历史 protected Test。

## 建议预注册的验收条件

以下是**设计目标，并非已经达到的指标**；应在看到 V0.2 结果前登记。

- 主收益：130、150、200 aa 三个长度的 MCP 召回率差值等权平均，V0.2 减 V0.1
  的配对 95% CI 下界大于 0。三个长度均需足够独立样本，不事后挑最好长度。
- 短序列假阳性：每个主长度的总体 MCP FPR 95% CI 上界不超过 1%，相对 V0.1
  的 FPR 增量 CI 上界不超过 **0.5 个百分点**。各阴性来源另表报告，不能用总体
  均值掩盖某类来源明显变差。
- 完整序列：MCP 召回率差值 CI 下界不低于 **-1 个百分点**，FPR 增量 CI 上界
  不高于 **0.5 个百分点**。
- 门分类：两个已知门分别报告，完整序列 H3 端到端召回率差值 CI 下界各自不低于
  **-1 个百分点**；上游漏检仍计入分母。
- 支持不足或区间不稳定时，不判定通过。零错误导致的零宽 bootstrap 区间不能证明
  总体错误率为零；需要补充独立样本或预注册适用于边界情况的区间方法。

当前 benchmark 提供每长度指标和配对差值；三长度综合指标、V0.2 训练和正式
验收判定属于后续工作。未达标时保留 V0.1，不自动升级版本。

## 工程交付与命名

科学评测通过后，再导出独立候选 bundle，记录训练数据、增强策略、编码器 revision、
分类头、temperature、阈值和经过验证的长度范围，并验证离线评分与推理包的一致性。
V0.1 保留为可选基线。

当前部署保护规则见上文。保留模型分数语义，不单凭长度宣称序列残缺。未来如有
独立证据，可另行版本化调整保护阈值。

满足交付要求后再分配科学模型标识并更新模型卡与[版本映射](../VERSIONING.cn.md)。
现有推理包的 `0.2.1` 是工程版本，不是科学模型 V0.2。此次不修改
`release-manifest.json` 或现有包版本。

原始长度分层 benchmark 已复用历史 embedding 在 CPU 上完成。当前数据在 250 aa
以下没有 MCP 阳性，250–299 aa 也仅有 13 条，仍不足以确定最短可用长度。后续需要
配对截短实验及独立短阳性验证来补足证据。新增片段的 GPU 编码与 V0.2 训练是另行
执行的步骤；本次没有训练 V0.2。
