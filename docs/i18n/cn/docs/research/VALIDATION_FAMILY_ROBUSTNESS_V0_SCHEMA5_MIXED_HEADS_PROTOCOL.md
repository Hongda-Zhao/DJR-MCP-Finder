# Project V0 八模型/混合头 Validation 家族稳健性方案

状态：schema 5，冻结的分析计划，辅助开发证据。它不替代 schema 4，不改变
已发布的 V0 模型，也不构成独立的 Test 评估。

分析 ID：`project_v0_validation_family_robustness_schema5_mixed_heads`。

## 0. 评分前修订 A

在无标签嵌入物化开始之后、但任何 schema-5 预测、端点、bootstrap 结果或模型
比较产生之前，完成了一次独立的契约审计。修订 A 更正了匹配家族中罕见 H3 的
分母（8 个成员关系/3 个亲本，与代表层级基准的 5 条记录不同），要求六项明确的
复用证明，加强断点续跑回执验证，并以校验和绑定 schema-4 连续性验证器/结果
清单。八个模型、九个混合候选、输入字节、冻结的头/阈值、CV 提名规则、
bootstrap 种子和 Test=0 边界均未改变。原始物化方案/配置快照（SHA256
`81aedf...881b6f` 和 `441990...adb94`）仍归档保留；修订后的评分重新证明其嵌入
输出，而不重新计算数值契约未发生变化的表征。

## 0b. 失败后运行修订 B

首次 CPU 评分尝试在 schema-4 连续性门禁处以失败关闭方式停止，当时尚未创建
稳定的结果目录、端点、bootstrap 结果、验证报告、图或候选解释。随后，一项单独
的只读诊断将全部 92,844 个 schema-4 预测键与新的 schema-5 推理进行了比较。
来源、聚类、依赖块、Train 关系、合格性、Test、真值、标签、预测、拒绝判定和
正确性字段完全相同；Test 仍为零，并且每个冻结阈值均被精确序列化。当时，非精确
值被归因于不同的 BLAS 批次形状：成员概率 114 行（最大绝对差
`3.353e-7`）、代表概率 684 行（`2.305e-7`）、成员原始分数 112 行（最大绝对值
`0.03125`），以及代表原始分数 684 行（最大绝对值 `0.0234375`）。报告的原始
相对值 `4.795e-7`/`3.590e-7` 属于最大*绝对*差所在的行；它们并不是全局最大
相对值。下文修订 C 同时取代了该因果归因和这些错误标注的极值。本段仅作为已冻结
的修订 B 上界在当时的理由而保留。

因此，修订 B 在任何正式 schema-5 结果产生之前冻结一项数值兼容性政策。仍须对
全部 92,844 行完成新推理，并逐行通过：

```text
probability:       abs(new-old) <= 5e-7 + 1e-6 * abs(old)
raw decision score: abs(new-old) <= 1e-5 + 1e-6 * abs(old)
threshold:         exact serialized equality
```

不得按模型或数据自适应地放宽。每一行的值和差值均保留在受校验和约束的审计表中。
独立验证器重新计算这些不等式，并从这些值推导二元判定、H3 拒绝状态和正确性。只有
在所有键、语义字段、空值模式、有限性/范围检查、精确阈值和派生判定全部通过之后，
才会以全有或全无方式执行替换：ESM-2 650M 和 ESM-C 6B 的精确、受校验和约束的
schema-4 序列化行成为 schema 5 中的规范预测缓存，并由这些规范行组成混合头。这消除
了依赖平台的末位漂移，而不改变嵌入、头、阈值、端点、候选排序或任何已发布的 V0
产物。

## 0c. 旧数值算子更正修订 C

修订 B 的科学边界采用失败关闭，但其数值诊断并不完整。Schema-4 作业 `4968695`
使用四个 BLAS 线程。该作业在后续步骤中的总体退出状态为 1；不得将其描述为成功
作业。不过，其预测生成和独立预测验证已经完成，且那些受校验和约束的
`predictions.tsv` 字节仍是规范连续性产物。第一次 schema-5 尝试 `4968800` 使用
12 个线程，并在精确连续性检查处、指标产生前停止。诊断 `4968804` 同样使用 12 个
线程，它把一个相对差附到了绝对差最大的行上；它没有计算最大逐行相对差，也没有对
每一行应用修订 B 的公式。因此，其汇总被误解成了全局界限。历史运行和诊断运行之间
的 HardNeg 全批次组成没有改变。复现出的原因是从四线程改为十二线程导致 OpenBLAS
归约方案变化，而不是批次形状变化。

发现该错误时，尚不存在稳定的 schema-5 结果、端点、bootstrap、验证、图或候选
解释。作业 `4968816` 再次在修订 B 原始分数门禁处、指标产生前停止。更正后的全行
12 线程诊断 `4968818` 显示：成员原始分数有 2 个违规，代表原始分数有 9 个违规，
而概率和阈值失败计数均为零。其独立采用的顶层最大相对值标量为：成员概率
`5.836859e-6`、成员原始分数 `5.253913e-6`、代表概率 `6.363661e-6` 和代表
原始分数 `1.201539e-6`；阈值精确一致。该诊断的详细
`max_relative_delta_record.ratio` 载荷存在显示缺陷（辅助函数使用
`limit=1.0`，所以该字段保存的是绝对差）。修订 C 不复用该记录字段：正式评分器和
验证器独立重新计算每个逐行差值及边界。这并非新的漂移。随后，使用历史数值算子测试
了一个结果产生前的重放假设。只读 cdb 作业 `4968820` 以退出状态 0 完成，并在
Python 3.11.7、申请四个 CPU、`OMP_NUM_THREADS=4`、`MKL_NUM_THREADS=4`、
`OPENBLAS_NUM_THREADS=4` 和 `PYTHONHASHSEED=20260724` 条件下比较全部 92,844
个键。Test 计数为零；全部五个数值字段的 `nonexact=0`，修订 B 失败数 `=0`。
作业 `4968820` 仅用于精确数值/有限性/Test 诊断：它没有审计每个语义字段，也没有
独立重新推导预测、拒绝和正确性值，因此不会被描述为正式的完整审计。

因此，修订 C 更正运行时算子，而不是更改容差。修订 B 的概率/原始值上界和精确阈值
规则保持冻结，且仍会重新计算。Schema-5 还要求全部 92,844 个规范
ESM-2-650M/ESM-C-6B 行的序列化数值精确重放。评分器必须在推理前证明四线程运行时
以及已加载 BLAS 线程池。为使所有线程池可观测，它首先只导入声明并冻结的数值模块
`scipy.linalg` 和 `sklearn.linear_model`；这不会执行任何拟合、评分或预测。随后，
它在任何推理前证明两个 BLAS 池加一个 OpenMP 池均使用四个线程。每个规范/重算值、
差值、语义字段、空值模式、有限性/范围检查、Test 标志、派生预测/拒绝判定和正确性值
都继续受校验和约束。任何非精确的数值字符串都会失败，即使它满足修订 B。只有在完整
的精确审计通过后，才可按全有或全无方式替换规范行，并将其用于混合头重组。

正式评分器在计算任何端点、bootstrap 或提名表之前，会完成全部键、语义、空值、
有限性/范围、派生判定、Test、精确字符串和保留上界门禁。随后，独立验证器根据受
校验和约束的逐行审计和运行时证明重建这些检查。因此，仅数值的 `4968820` 证据可为
算子更正提供依据，但其本身不能授权 schema-5 结果。

这只是一项运行重放更正。嵌入、拟合的头、温度、阈值、Test 政策、bootstrap 种子、
CV 分数、候选网格、稳健性端点和已发布的 V0 产物均未改变。没有声称作业 `4968695`
整体通过；仅使用了其已经过验证的预测产物及其现在已独立重放的数值算子。

## 1. 问题与证据边界

此分析询问：已通过正式 14 模型基准门禁的八个表征模型，在相同的四个特定来源
Validation 家族队列上是否表现一致；以及预声明的双编码器级联是否是适合后续外部
确认的候选。

所有表征检查点、仅在 Train 上拟合的头、温度、决策阈值、H3 拒绝阈值、合法队列
排除项和依赖块均保持冻结。Schema-5 输出不得反馈到拟合、校准、阈值调优、已发布的
V0 工具或 Test 中。混合级联最多只能称为 `recommended_for_external_confirmation`，
绝不能称为已获独立验证或在生产中更优。

永久计数器：

```text
training_operations=0
calibration_fit_operations=0
threshold_tuning_operations=0
Test vectors selected for inference=0
Test predictions or performance metrics computed=0
released_V0_artifacts_modified=0
```

## 2. 为何恰好选择这八个模型

模型集合在 schema-5 推理前，从现有受校验和约束的 14 模型基准中固定：

`esm2_650m`、`esm2_3b`、`esmc_300m`、`esmc_600m`、`esmc_6b`、`prott5_xl`、
`prostt5` 和 `esm3_open_1_4b`。

其他六个基准模型仍在 14 模型开发图中显示，但不进入这项昂贵的稳健性扩展，因为它们
没有通过预声明的主要候选边界。Schema-5 结果不得追溯性地添加或删除模型。

## 4. 同构候选与混合候选

首先，在来源支持相应头的情况下，八个模型分别提供 H1、H2 和 H3。这些同构运行用于
诊断特定表征的失败，不会被平均成一个四来源分数。

主要混合头搜索仅限九个预声明的级联：

```text
H1=H2 in {ESM-2 650M, ESM-2 3B, ESM-C 6B}
H3    in {ESM-C 300M, ESM-C 600M, ESM-C 6B}
```

H1 和 H2 必须共享一个编码器，因为 H2 已经饱和，而且第三个始终开启的编码器在运行
上没有合理依据。只有当 H1→H2 路由到达病毒 VMA-DJR 后，才调用不同的 H3 编码器。
主要结果中不允许从其余 `8^3` 种组合中依数据添加候选。

## 5. 端点

各来源分别报告：

- 病毒：H1 敏感性、H2 条件敏感性、H1→H2 路径召回率、H3 已知两门 macro-F1、
  两个已知门各自的 F1 值、Produgelaviricota 拒绝召回率、文献未分类拒绝召回率，
  以及仅作为次要小样本诊断的合并拒绝召回率；
- 细胞：H1 敏感性、H2 特异性和 H1→H2 非 MCP 路径正确召回率；
- 背景和匹配 HardNeg：仅 H1 特异性/FPR；
- 每个适用来源：成员层级比率和 `all legal members correct` 来源聚类比例。

H3 `unknown` 表示拒绝行为，而不是通用的未知病毒检测。正式的代表层级基准有五条
罕见 Validation 记录。匹配家族稳健性分片包含来自三个 Validation 亲本的八个合法
罕见成员关系（Produgelaviricota 7 个，加上 literature-unclassified 1 个）。两个
亚组的分母及其原始成员/亲本 `k/n` 必须分别显示。一个 literature-unclassified
记录仅具描述性，无法支持推广。`8/3` 合并值为次要结果；这些拒绝端点均不进入已知门
macro-F1。背景或 HardNeg 的 H2/H3 为 `N/A`，而不是零。

## 6. 不确定性与比较

使用 10,000 次确定性嵌套 bootstrap 重复，种子为 `20260728`。外层单位是冻结的
共享-SHA/原始组件依赖块；成员保持嵌套在其来源聚类内。模型和混合级联的差值使用相同
的 bootstrap 抽样。报告百分位数法百分之九十五区间。以冻结的全 ESM-C-6B 级联为
基准，使用族范围 Holm 校正比较八个非平凡主要混合候选；第九个候选是全 6B 自身
参照，其差值为零，不进行假设检验。还报告与全 ESM-2-650M 在细胞/背景/HardNeg
优势上的情境性配对差值，但不得据此重排候选。禁止未经校正的探索性声称。冻结的
等权块→聚类→成员估计和严格的所有成员均正确聚类比例都必须显示，因为两者回答不同
的问题。

## 7. 候选提名规则

不对稳健性做优化。候选顺序首先由现有的、仅基于 Train 的五折值确定：

`S = 0.60 × H1 AP + 0.30 × H2 AP + 0.10 × H3 known macro-F1`。

对于混合候选，H1/H2 的折值来自其共享基础模型，H3 来自相同冻结折上的 H3 模型。
平均 `S` 最高者为准确率优先的提名候选。如果候选位于该最大值的一个配对折标准误
之内，则报告 Pareto 集，并依次优先选择：更低的始终开启基础编码器每条序列 GPU
秒数、更低的最坏情况双编码器 GPU 秒数、更低的 GPU 峰值内存，然后是冻结的词法
候选 ID。

Schema-5 稳健性不得改变此 Train-CV 提名顺序。当经 Holm 校正的配对区间确认相对
全 ESM-C-6B 有所退化时，它会提供特定来源警告；该警告必须伴随提名候选，并阻止任何
生产替换，直到来源-组件不相交或前瞻性外部数据集确认它。

成本以两项报告——始终开启的 H1/H2 编码器加上条件式 H3 编码器——并报告最坏情况
总和。若不说明假设的路由流行率，则不声称一个依赖流行率的单一运行时间。

## 8. 完成与失败关闭规则
